# 场景与示例

这些模式用于设计提示词；直接撰写业务产物时，按用户任务执行，不为套 Skill 额外生成一份提示词。

## 商业研究写作模式

适合已有资料到观点明确的文章、研究简报。

```text
依据提供的资料，为【读者】写【主题】分析，服务【具体决策】。
先提炼可核实事实，再说明推断及其依据，最后给出行动选项和限制。
每项关键事实附可定位来源；来源未覆盖的数字和用户反馈不补写。
按当前资料判断证据强弱；来源冲突时写清口径、时间和未解决之处。
输出以结论开头，正文按论点组织；语言简洁，保留必要的反证。
```

## 周报提示词模式

适合把真实记录变成团队、项目、管理层、销售或营销周报。

```text
使用【周期】内的工作记录与指标，为【受众】整理周报。
先说明本周结果，再写同口径变化、影响交付的阻塞、需要的决策与下期行动。
区分已完成、进行中、计划和推测。责任人、日期、同比环比必须有输入依据。
没有上期数据就不计算变化；没有负责人就标记待明确，不替团队作承诺。
只保留对当前受众有用的部分，附关键记录来源。
```

## 完整改写示例

输入提示词：“你是顶级产品经理，帮我写一个完美周报，数据不全就合理补充。”

问题：目标受众未知；“完美”不可验收；允许编造数据。

可使用的替代稿：

```text
根据我提供的本周记录整理中文产品周报，默认面向项目协作成员。
输出：本周成果、指标变化、阻塞与风险、下周行动。
已发布、已测试、开发中和计划事项分别标明真实状态，不把计划写成成果。
只有输入同时包含本期与可比上期数值时才计算变化，缺失项写“未提供”。
每个阻塞说明影响、已有应对及需要谁做什么；未知责任人写“待明确”。
如受众或周期缺失会改变内容，提出具体问题；同时整理已有材料能支持的部分。
```

验收：输入只含本周新增用户 120、功能仍在测试时，输出不得出现上周数值、增长百分比或“正式上线”。这是一条设计用例；运行模型并保存输出后才能报告它通过。
